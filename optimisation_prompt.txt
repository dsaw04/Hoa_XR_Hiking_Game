I need a performance optimisation pass on this Unity project. Target platform is Meta Quest 3 (standalone Android, mobile GPU), built with the XR Interaction Toolkit. The project follows a code-first convention: no prefabs, runtime-built world-space canvases via a shared VRPanel helper, TextMeshPro/SDF for text, and procedurally placed vegetation in distance-based bands.

Before changing anything, investigate and report on:

1. **Draw calls & batching** — identify anything preventing static/dynamic batching or GPU instancing, especially in the procedural vegetation system (check if it's spawning individual GameObjects vs instanced meshes).
2. **GC allocations per frame** — look for allocations in Update/FixedUpdate loops, LINQ usage in hot paths, string concatenation, boxing, and foreach over non-generic collections. VR is unforgiving of GC spikes (frame drops = motion sickness).
3. **UI canvas overhead** — since canvases are built at runtime, check for excessive canvas rebuilds/layout recalculation, overlapping raycast targets, and whether world-space canvases are unnecessarily set to update every frame.

5. **Shaders & materials** — flag any non-mobile-optimised shaders, unnecessary transparency/overdraw, and material instances that could be batched via shared materials or GPU instancing.
6. **Texture memory & compression** — verify ASTC compression is used, check texture sizes vs actual on-screen size, mipmap settings.
7. **Rendering settings** — confirm fixed foveated rendering / URP mobile renderer settings are configured correctly for Quest 3, and check MSAA/resolution scale settings.
8. **Terrain/vegetation generation cost** — since vegetation spawns in 5 distance-from-centre bands, check whether generation happens once or repeatedly, and whether LOD/culling is applied to distant vegetation.

For each issue found, report: file/location, why it's a problem specifically for standalone VR performance, and the estimated impact (draw call count, allocation size, etc.) before proposing a fix.
